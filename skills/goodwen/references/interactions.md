# 结果、卡片与个人后续

## 按用户目的交付

培训反馈呈现分数、薄弱点和复习方向；面试参考结合具体回答给出考察重点；偏好测评解释实际维度；需求调研归纳主题、分歧与追问。没有评分规则时不生成总分，没有类型映射时不编造人格类型。

个人解释、少量反馈或下一步建议直接用对话和表格。汇总前取齐当前筛选范围的全部分页；结论引用实际回答与题号，不把列表前十行当成总体。

## 四个展示入口

| 用户动作 | 展示工具与范围 |
| --- | --- |
| 查看新建或修改的问卷 | `questionnaire_summary_show(draft_id)`：摘要、题量与真实 Goodwen 查看入口 |
| 查看回答或本轮处理结果 | `response_list_show(scope, ...)`：实际分数／建议分、维度和逐份摘要；保存过的运行传 `processing_run_id` |
| 汇总分析或展开依据 | `questionnaire_analysis_show`：同一完整 `scope`、`purpose`、`conclusion`、实际 `analyzed_result_ids` 和 `sections` |
| 查看今日关注 | `attention_inbox_show`；纯数据读取可用 `attention_inbox_get` |

卡片由远程 MCP 提供。只在这些用户里程碑展示卡片，不为分页、详情或每批回执增加卡片。宿主不渲染时，用文字、表格和返回链接完成任务，不宣称曾展示或点击卡片。

分析区块按实时 schema 使用 `text`、`metrics`、`bars`、`table`，指标须由实际回答计算。提供相关 `result_ids`、必要的 `question_id` 和有意义的后续动作；展开或全屏依赖宿主，普通对话仍可继续。

## 接住卡片发来的意图

- “下一步建议”只读取指定 `result_id`，保持本次问卷、目的与题目范围，直接交付个人考察／学习／访谈建议。发现疑点不自动发补答问卷。
- “汇总分析”“整体建议”沿用完整筛选范围；用户选中几份回答时仅处理所选记录，不扩大到整份问卷。
- 今日关注中的“查看结果”回读已保存成果；“处理剩余”只补未完成项，展示范围仍包含已完成与本次处理的全部回答。评分后不要因原来的待评分筛选把成功处理的记录丢出结果。
- “一键处理剩余”保持每份问卷独立的范围和目的，复用已有成果，按[批量处理](processing.md)完成剩余项。
- “自动处理新回答”只是把意图交给宿主，转入[定时与事件处理](automation.md)。消息投递成功后不能直接声称任务已创建。

后续动作重新读取当前业务状态。使用服务返回的 `detail_url`、`collection_url`、`review_url`；保持问卷、版本、时间及状态筛选，不自行拼链接，也不让用户手抄内部 ID。

## 从指定答卷生成后续问卷

只有用户明确要求“基于这次回答生成练习／追访问卷”时才执行：

1. `result_get` 读取指定答卷、冻结题目、已有评分与 `followups`，确认来源及是否已有适用的后续内容。
2. 按作者指南调用 `questionnaire_draft_create`，传完整 `source_qml`、准确 `source_result_id`、`workspace_id` 和幂等键；该操作同时需要 `results:read` 与创作权限。返回正常的草稿摘要与审核链接。
3. 真人批准后，若用户明确要求给原参与者创建入口，将原答卷的 `participant.id` 作为 `participant_id` 调用 `distribution_invitation_create`，使用新问卷已批准的 `release_id`。不重复索要手机号，不自动发送消息。
4. 读取原答卷的 `followups` 跟进后续回答。已存在的后续草稿／邀约先回读；重试复用原幂等键，不能生成重复问卷或邀约。

## 示例请求

> 看看今天哪些问卷需要关注，复用已有分析，只处理剩余回答。

> 解释这份回答的薄弱点，并给出下一次访谈的考察重点。

> 根据这份答卷生成三道针对性练习，先交给我审核；批准后再为同一参与者创建作答入口。
